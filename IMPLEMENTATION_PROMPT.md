# Paradox Discord Bot — план покращень

Цей файл замінює попередню версію ТЗ. Стара версія була згенерована з code review
і містила **фактичні помилки про код**: вона описувала дві фічі, яких у боті не було
(кнопки під ембедом і робоче завантаження на pdx.tools), переплутала джерело блокуючого
I/O, і при цьому пропустила всі критичні баги. Вона також вимагала архітектуру
(кеш із TTL, власний rate limiter, admin-cog, Flask-API з CORS), непропорційну боту
на 311 рядків із локальною базою на ~1900 записів.

Нижче — те, що реально було не так, що вже виправлено у **v0.0.2**, і що лишається.

---

## Зроблено у v0.0.2

### Безпека і коректність

1. **Ін'єкція аргументу команди → path traversal.** Було:
   ```python
   @bot.command(name=key)
   async def game_command(ctx, query: str, game_key=key):
   ```
   `game_key` мав дефолт, але лишався звичайним позиційним параметром, тому discord.py
   дозволяв передати його з чату. Перевірено на старому коді:
   `-eu4` мав параметри `['query', 'game_key']`, а `db_path("../../etc/foo")` повертав
   `databases/../../etc/foo.db` — і `sqlite3.connect()` створював цей файл.
   Далі `log_request` падав з `KeyError`.

   Виправлено: ключ гри захоплюється замиканням фабрики `make_command()`, а не дефолтним
   аргументом. `db_path()` додатково відхиляє все, чого немає в `GAME_STYLES`.

2. **Багатослівні запити обрізалися.** Через ту саму сигнатуру `-eu4 holy roman empire`
   шукав лише `holy`. Тепер `*, query: str` — параметр keyword-only, забирає весь залишок рядка.

3. **Незакриті з'єднання SQLite.** `with sqlite3.connect(...)` комітить транзакцію, але
   **не закриває** з'єднання — на кожен пошук витікав дескриптор. Тепер `try/finally
   conn.close()`, `row_factory = sqlite3.Row`, `timeout=5` і `mode=ro` через URI
   (відсутня база тепер кидає помилку, а не створюється порожньою).

4. **Синхронний SQLite в event loop.** Це і є справжня блокуюча операція — не збереження
   вкладення (`attachment.save()` у discord.py уже асинхронний, `aiofiles` не потрібен).
   Запити до БД тепер ідуть через `asyncio.to_thread`.

5. **`%` і `_` у запиті працювали як LIKE-wildcards.** Додано `escape_like()` + `ESCAPE '\'`.

6. **`LOG_CHANNEL_ID` парсився на кожен запит** без перевірки → `TypeError`, якщо не заданий.
   Тепер читається один раз на старті; збій відправки в канал більше не валить команду.

7. **Персональні дані в репозиторії.** `pdx_tools.db` з реальними `user_id` користувачів
   Discord, чужий сейв на 12 МБ у `temp/`, і `WIKI.pid` були закомічені. Прибрано з індексу
   й додано в `.gitignore`.

### Функціональність

8. **`-tools` нічого не завантажував.** URL просто склеювався з імені файлу
   (`https://pdx.tools/uploads/{filename}`), жодного HTTP-запиту не було — бот показував
   користувачу неробоче посилання і зберігав його в БД.

   Реалізовано справжнє завантаження за документованим API pdx.tools: HTTP basic auth
   (user id + API key), заголовок `pdx-tools-filename`, тіло POST — байти сейву
   (multipart не підтримується), zip іде як є, решта стискається gzip. Запис у `Uploads`
   і посилання користувачу — **тільки після успішної відповіді API**. Без ключів у `.env`
   команда чесно каже, що аплоад не налаштовано.

   Вкладення читається в пам'ять (`attachment.read()`) замість запису в `temp/` — зникають
   і сміття на диску, і шлях, куди потрапляє ім'я файлу від користувача.

9. **`LinksView` був мертвим кодом** — визначений, але ніколи не передавався в `ctx.send()`.
   Кнопок, які описувало старе ТЗ, у боті не існувало. Тепер підключений через `view=`.

10. **Немає обробника помилок.** `-eu4` без аргументу давав тишу користувачу і трейсбек
    у stderr; `-abc` кидав `CommandNotFound`. Додано `on_command_error`.

11. **`search_similar` — мертвий код**, видалено. **`-help`** генерується з `GAME_STYLES`,
    а не хардкодиться. **`write_pid()`** більше не виконується на імпорті.

12. **`print()` → `logging`** з ротацією у `logs/bot.log`. Типи й докстрінги додані.

### Пакування

13. `pyproject.toml` змішував PEP 621 і Poetry, мав порожні `dependencies` і коментар
    українською всередині TOML-рядка. Переписаний як чистий PEP 621, версія `0.0.2`.
    `requirements.txt` доповнений (`flask` бракувало). Протухлий `uv.lock` від
    неіснуючого проєкту `python-template` видалений. Додані `.env.example` і `README.md`.

**Свідомо збережено:** імена команд і префікс `-`, стилі та кольори ігор, тексти
українською, реакції ✅/❌, змінна `TOKEN` (стара версія ТЗ пропонувала перейменувати її
на `DISCORD_TOKEN`, що суперечило її ж вимозі зберігати сумісність).

## Далі: етап 1 — якість пошуку

Найбільша цінність для користувачів і найдешевша в реалізації.

- **Підключити `Redirects`.** У базах лежить 7069 редиректів для eu4, 4708 для stl,
  2204 для vic3 — це готові синоніми й альтернативні назви сторінок, які зараз просто не
  читаються. Шукати другим рівнем після `Pages`, віддавати `target_page_url`.
- **Ранжування.** Зараз часткові збіги сортуються за алфавітом. Потрібно:
  точний збіг → збіг з початку назви → входження в середині; всередині групи —
  за довжиною заголовка (коротше = релевантніше).
- **Індекс.** `LOWER(REPLACE(title,'_',' '))` — обчислюваний вираз, тому індекс по `title`
  не працює і кожен пошук робить full scan. На ~1900 рядках це непомітно, але правильно —
  expression index або окрема FTS5-таблиця, що будується разом з оновленням даних.

## Далі: етап 2 — структура

Плаский `src/` на 5 файлів, **не** 5 пакетів:

```
main.py              # точка входу
src/config.py        # GAME_STYLES + env
src/db.py            # search_pages / search_redirects / record_upload
src/logging_setup.py
src/cogs/wiki.py     # команди ігор, -help, -tools
src/keepalive.py
```

**Не робити:** `SearchCache` (запит до локального SQLite — частки мілісекунди, кеш додає
лише несвіжість), власний `RateLimiter` (у discord.py є `@commands.cooldown` і
`@commands.max_concurrency`), `AdminCog`, `/stats/cache`, `/health/ready`, CORS.

## Далі: етап 3 — тести й CI

`pytest` на чистих функціях: `normalize`, `escape_like`, `search_pages` на тимчасовій БД,
ранжування, `prepare_save_payload`, `_extract_save_url`. Інтеграційні тести з моками
Discord — пропустити, співвідношення користі до зусиль погане.
GitHub Actions: `ruff` + `pytest` (одна тулза замість black+pylint+mypy).

## Далі: етап 4

- **Slash-команди** (`app_commands`) з автодоповненням назв сторінок. Це не косметика:
  `message_content` — привілейований інтент, і після 100 гільдій його треба верифікувати.
- **Скрипт оновлення баз** з вікі — зараз дані статичні й неминуче протухнуть, а скрейпера
  в репозиторії немає.
- **Обробник реакцій** ✅/❌ або їх видалення — зараз вони декоративні.
- `Dockerfile`. `.replit` має `deploymentTarget = "cloudrun"`, що для довгоживучого бота
  неправильно — Flask keep-alive є милицею саме проти цього.

## Верифікація

Прогін проти реальних `databases/*.db` (усе пройдено на v0.0.2):

- багатослівний запит `holy roman empire` знаходить `Holy Roman Empire (country)`;
- `-eu4 Ottomans` віддає точний збіг першим;
- `%` і `___` як запит дають 0 результатів, а не всю таблицю;
- `db_path("../../etc/passwd")` кидає `KeyError`; нові файли в `databases/` не з'являються;
- у кожної з 6 команд рівно один параметр `query`, і він `KEYWORD_ONLY`;
- 50 послідовних пошуків не збільшують кількість відкритих дескрипторів;
- zip проходить без змін, не-zip гзіпається і розпаковується назад побайтово;
- `_extract_save_url` відхиляє не-JSON, JSON без id і масив.

Потрібен живий прогін (недоступний в CI-пісочниці): `-tools` з реальними
`PDX_TOOLS_USER_ID` / `PDX_TOOLS_API_KEY`. Домен pdx.tools заблокований egress-проксі
середовища розробки, тож код написаний за документованим контрактом, але не перевірений
проти живого сервісу. Точний шлях ендпоінта і шаблон посилання винесені в
`PDX_TOOLS_API_URL` / `PDX_TOOLS_SAVE_URL` — якщо вони не збігаються з реальним API,
це правиться в `.env`, без зміни коду.
